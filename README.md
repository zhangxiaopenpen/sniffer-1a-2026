# 网络嗅探器课程项目

这是一个面向 Windows 的网络嗅探器课程项目，使用 Python、Scapy 和 PySide6，按阶段逐步实现并验收。

仓库地址：<https://github.com/zhangxiaopenpen/sniffer-1a-2026>

## 当前进度

阶段 0、阶段 1、阶段 2 已通过用户审核。阶段 3 已实现协议/IP/CIDR/端口显示筛选、经典 PCAP 导入和文件模式生命周期；阶段 4 已实现域名证据与 DNS 关联，当前等待用户验收。阶段 5 至阶段 6 尚未开始。

每个阶段完成并推送后，由用户验收，通过后再继续下一阶段。提交记录以 Git 历史为准。

## 本机快速开始

请使用新项目目录 `sniffer_1a_git`，不要进入旧目录 `sniffer_1a`。本项目的独立 `.venv` 已创建并安装依赖，本机 Npcap 服务正常，无需安装新依赖或激活环境。打开 PowerShell，直接运行：

```powershell
Set-Location 'D:\研一课程\软件与系统安全\sniffer_1a_git'
.\.venv\Scripts\python.exe -X utf8 .\main.py
```

窗口打开后，选择带“默认建议”标记的网卡，点击“开始抓包”，等状态显示“正在抓包”后访问常用网页。点击“停止”，等待“已停止”且“待处理 0”，再查看数据包、应用筛选或点击“保存 pcap”。也可以点击“打开 pcap”导入已有经典 PCAP。完整操作见 [阶段 3 验收流程](docs/阶段3验收流程.md)。

## 阶段 2 图形界面

- 网卡列表显示名称、IPv4、默认建议和回环标记。回环测试请选择带 `[回环]` 标记的接口，开始后在第二个 PowerShell 窗口运行 `ping 127.0.0.1`。
- 默认最多保留 1000 包，可在空数据状态下调整为 10–10000 包；达到包数上限或 32 MiB 原始数据预算时自动停止。
- 表格按捕获顺序显示编号、时间、源地址、目的地址、协议、源端口、目的端口、长度，共八列。选中一行可查看协议字段和捕获时的十六进制原始数据。
- 手动停止后仍会整理待处理包；后台退出且待处理为零后，才可保存、清空或继续。同一网卡可继续累计到当前数据集；更换网卡或调整上限前需先清空。
- 保存为 PCAP 文件，使用保存对话框实际选定的路径。保存期间暂停其他数据操作；保存失败时保留窗口中的包和原有目标文件，可换路径重试。

请在“清空”或退出前自行保存需要的数据，程序不会自动保存，也没有未保存提示。抓包期间关闭窗口会异步等待后台退出并整理剩余包，然后关闭；这不等于保存。停止或关闭时窗口仍处理界面事件，但驱动永久无响应时仍可能持续等待。若保存过程中关闭窗口且保存失败，会取消关闭并保留数据。

计数中的“收到”仅统计进入本程序回调的包，满足 `收到 = 保留 + 应用丢弃`；“保留”包含已显示和待处理。停止并排空后，“保留”和“已显示”应相同，保存数量与这两项一致，不要求等于“收到”。“应用丢弃”不是网卡或 Npcap 的总丢包统计。

抓包线程不向界面逐包发送信号；界面每 100 ms 最多追加 250 包。待处理缓存限制为 2048 包或 8 MiB 原始数据，避免界面来不及消费时无限堆积；32 MiB 是保留包的原始字节预算，不是 Python 进程总内存上限。

## 阶段 3 过滤与经典 PCAP 导入

- 表格上方的“显示筛选”支持“全部、HTTP、TCP、UDP、IPv4、IPv6、ICMP、ICMPv6”。IP 输入框接受单个地址或 CIDR，端口输入框接受 0–65535；协议、IP 和端口条件同时填写时按 AND 组合，IP 和端口均匹配任一端。按 Enter 也可以应用筛选。
- 筛选只改变表格显示，不删除保留数据；保存时仍保存全部源数据。筛选后选择行，详情会映射回源数据并显示原始捕获字节。非法条件会保留上一组有效筛选。
- “打开 pcap”使用后台线程读取经典 PCAP 2.4（支持常见微秒/纳秒、大小端格式），成功后替换当前数据并进入文件模式。读取失败或取消会保留原数据；导入期间开始、清空、保存和重复导入会被锁定。
- 文件模式下可以继续筛选、查看详情和保存；点击“清空”后恢复实时抓包。程序明确拒绝 PCAPNG，不实现域名分析、TCP 流重组或跨 TCP 分片的 HTTP 识别。

阶段 3 的具体操作、失败保护和验收命令见 [阶段 3 验收流程](docs/阶段3验收流程.md)。

## 阶段 1 命令行入口

原命令行入口仍可使用，在上述新项目目录中运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 .\sniffer_cli.py --help
.\.venv\Scripts\python.exe -X utf8 .\sniffer_cli.py --list
.\.venv\Scripts\python.exe -X utf8 .\sniffer_cli.py
```

无参数运行时会列出网卡并提示选择：输入本次列表序号或精确名称，回车选择有“默认建议”标记的网卡，输入 `q` 取消。默认最多捕获 20 个包、等待 30 秒，以先达到者为准；也可按 `Ctrl+C` 停止。

测试本机回环通信时，可直接使用 `loopback`，无需猜测网卡名称：

```powershell
.\.venv\Scripts\python.exe -X utf8 .\sniffer_cli.py --iface loopback --count 0 --timeout 20
```

看到“抓包已就绪”后，在**第二个 PowerShell 窗口**执行 `ping 127.0.0.1`，让流量产生在抓包期间。回环接口也可能包含其他本机流量，输出较多属于正常情况；本阶段不支持协议筛选。逐项操作见 [阶段 1 验收流程](docs/阶段1验收流程.md)。

## 阶段 1 命令说明

| 参数 | 行为 |
| --- | --- |
| `--list` | 列出序号、名称、描述、IPv4、默认建议/回环标记和设备标识后退出 |
| `--iface` / `-i` | 选择本次列表序号、精确名称/描述/设备标识，或回环别名 `loopback` |
| `--count` / `-c` | 非负整数，默认 `20`；`0` 表示不限数量 |
| `--timeout` / `-t` | 非负有限秒数，可为小数，默认 `30`；`0` 表示不限时间 |

数量与超时同时生效，以先达到者为准；两者均为 `0` 时持续抓包，使用 `Ctrl+C` 停止。非交互环境必须提供 `--iface`。列表序号只对应本次枚举，脚本调用优先使用 `loopback` 或精确设备标识。

每个包显示序号、时间、字节长度及 Scapy 摘要，结束时显示本程序收到的包数。命令行入口使用 `store=False`、`promisc=False`，不保留包列表，不保存抓包文件，也不提供 GUI、协议筛选或协议分析界面；图形界面请运行 `main.py`。

## 其他机器首次准备环境

需要 Windows、Git、Python 3.14.3（包含 `py` 命令）和 Npcap。直接依赖固定为 Scapy 2.8.0、PySide6 6.12.0，见 `requirements.txt`；本机已安装，无需重复准备。

Npcap 是需单独安装的 Windows 驱动，不能通过 `pip` 安装。先检查是否已安装；未安装时从 <https://npcap.com/#download> 获取，并启用 WinPcap API 兼容选项。若驱动限制为管理员访问，请以管理员身份打开 PowerShell。

在希望存放项目的文件夹打开 PowerShell，下载项目；已有项目时直接进入实际项目路径：

```powershell
git clone https://github.com/zhangxiaopenpen/sniffer-1a-2026.git
cd sniffer-1a-2026
```

仅在尚未准备环境时，在项目目录内检查 Python 版本、创建独立虚拟环境并安装依赖：

```powershell
py -3.14 -X utf8 --version
py -3.14 -X utf8 -m venv .venv
.\.venv\Scripts\python.exe -X utf8 -m pip install -r requirements.txt
```

验证 PySide6 和 Scapy 能否导入，并检查依赖冲突：

```powershell
.\.venv\Scripts\python.exe -X utf8 -c "import PySide6; import scapy; print('PySide6:', PySide6.__version__); print('Scapy:', scapy.__version__)"
.\.venv\Scripts\python.exe -X utf8 -m pip check
```

版本输出应分别为 `6.12.0` 和 `2.8.0`；依赖检查正常时会输出 `No broken requirements found.`。这些检查只验证 Python 依赖，不代表已经验证真实抓包。

## 阶段 4 域名证据与 DNS 关联

阶段 4在停止后的稳定快照或成功导入的经典 PCAP 上执行后台域名分析。点击“分析域名”后，表格会在原八列后增加“域名”和“依据”两列，详情显示 DNS 查询/应答的 transaction ID、QNAME、QTYPE、A/AAAA/CNAME、TTL、关联包号，以及同一 TCP 包内的 HTTP Host/TLS SNI。

域名条件可以和协议、IP/CIDR、端口条件同时使用，按 AND 组合。DNS/IP/TTL 共享地址线索始终标为候选证据，默认不参与确定域名筛选；勾选“含候选”后才会纳入。分析使用 generation、稳定包对象快照和可取消后台线程，开始新捕获、清空或替换文件会使旧结果失效，取消或失败不会提交半成品。

解析器只读取包内完整字段：不进行外部 DNS 或反向查询，不调用 `socket`、`getaddrinfo` 或 `Resolve-DnsName`，不实现 DoH/DoT/DoQ、HTTPS 解密、PCAPNG、跨 TCP 分片重组和阶段 5 TCP 流。完整操作见 [阶段 4 验收流程](docs/阶段4验收流程.md)。

所有 `.pcap`、`.pcapng` 文件默认忽略，避免提交真实抓包数据。抓包日志与临时验证脚本仅保留在本地，不提交。后续如需提供示例，仅在审核合成样本后，按具体文件路径显式允许提交。
