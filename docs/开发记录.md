## 阶段 4：域名证据、DNS 关联与进阶基础 DNS 统计（2026-11-24）

### 设计与实现

- 采用“证据索引+表格列”方案：新增 `domain_models.py`、`domain_parsers.py`、`domain_analysis.py` 和 `domain_ui.py`。
- 解析单个完整数据包中的 DNS 查询/应答、HTTP Host 和 TLS ClientHello SNI；DNS 事务同时校验客户端/解析器双向端点、UDP/TCP、transaction ID、QNAME、QTYPE 和 30 秒时间窗口。
- A/AAAA 地址映射只生成 DNS/IP/TTL 候选证据，默认不参与确定域名筛选；所有证据保留原始包编号。
- `PacketTableModel` 在分析完成后追加“域名”“依据”列；域名条件和协议、IP/CIDR、端口条件按 AND 组合。
- `DomainAnalysisWorker` 固定包对象快照，在后台线程可取消运行；generation、数据集编号和包对象身份用于拒绝陈旧结果。
- `AnalysisStats` 从完整稳定分析结果构建五项统计：DNS 查询数、DNS 响应数、成功匹配事务数、未匹配查询数和唯一直接域名数；GUI 以“DNS统计”标签显示。
- 保存仍写入全部原始包，界面生成的域名索引不写入 PCAP。

### 进阶基础 DNS 统计

- 统计输入是停止并排空后的稳定包快照，或成功导入后固定的数据集；五项值在分析完成后一次性提交，表格筛选只改变显示行，不改变统计值。
- “DNS 查询数”和“DNS 响应数”统计包内完整、可解析的 DNS 消息；“成功匹配事务数”只统计同时具备查询和响应且通过端点、传输层、transaction ID、QNAME、QTYPE 和时间窗口校验的事务；“未匹配查询数”统计没有关联响应的查询。
- “唯一直接域名数”对直接证据去重。DNS/IP/TTL 候选证据保留在行证据中，但不计入该指标。
- 畸形、跨包、超出包数或原始字节预算的报文不计入可解析统计；取消分析、清空、开始新的捕获或成功导入新数据集都会使旧统计失效并恢复“DNS统计：尚未分析”。

### 明确边界

本阶段不调用外部 DNS、反向解析或系统网络解析 API，不实现 DoH/DoT/DoQ、HTTPS 解密、PCAPNG、跨 TCP 分片 HTTP/TLS/DNS 重组和阶段 5 TCP 流。不会调用 `socket`、`getaddrinfo` 或 `Resolve-DnsName`，也不会把统计或域名索引写入 PCAP。畸形、截断、时间戳无效或预算超限的报文只保留安全说明，不猜测域名。

## 阶段 5 — 双向 TCP 流与跨段证据（2026-11-24）

### 设计与实现

- 采用独立 TCP 流分析模块，流结果与阶段 4 的域名结果、DNS 统计分开保存。稳定快照仍使用源包行号，筛选后的代理行不会替代原始包编号。
- `tcp_models.py` 定义 IPv4/IPv6 端点、双向流键、片段和会话边界；`tcp_reassembly.py` 按序号窗口还原连续载荷，处理 32 位序号回绕、乱序、重传、重叠冲突和缺口。使用有界字节数组，避免按巨大序号跨度无界分配。
- `tcp_transport.py` 按最外层 IP 长度和 TCP `dataofs` 提取应用字节，排除链路填充、IP 分片、隧道和 ICMP 引用中的误匹配。
- `tcp_application.py` 从可靠连续载荷起点解析完整 HTTP/1 请求头的唯一 Host，或完整 TLS ClientHello 的 SNI；支持 ClientHello 跨 TCP 段和跨 TLS 记录，并校验长度、重复扩展和畸形字段。
- `stream_models.py` 保存预算、流摘要、源包映射和证据；`stream_analysis.py` 负责有界聚合和可取消后台分析。新的初始 SYN 对应新会话，旧会话记录保留。
- `stream_ui.py` 通过 generation、数据集来源和包对象身份校验完整结果。GUI 增加“追踪 TCP 流”、摘要和“TCP流/流方向/流状态”三列。默认 8 列，仅域名分析 10 列，仅流分析 11 列，两种结果共存为 13 列。
- `window_presentation.py` 承接窗口状态呈现、显示筛选和详情操作，主窗口文件保持 499 行；本阶段新增源码文件均不超过 500 行。
- 流详情展示规范化 A/B 端点、方向、观察到的状态、连续字节数、重复/重叠字节和源包号。A/B 不表示客户端/服务端，包号始终对应原始数据集。

### 完整性与资源边界

- 确定 Host/SNI 要求请求方向观察到初始 SYN，且整个流没有缺口、重叠冲突或预算截断。只有 SYN+ACK 不作为已看到客户端初始请求的依据。中途抓包仍展示流，但不发布确定域名。
- 默认分析预算为 10000 包、1024 会话、每流 4096 段、每方向 2 MiB 缓存载荷、总载荷 32 MiB。存储预算保守计入重传载荷，重组序号窗口另有上限；预算不等同进程总内存上限。
- TLS SNI 属于明文握手字段；有 ECH 时仅标注外层名称，不能确认真实目标域名。未实现 HTTPS 解密、IP 分片重组、QUIC/HTTP3、进程追踪或外部 DNS。
- 阶段 4 域名筛选不自动纳入流证据。单包字段可见与整个流可靠是不同结论，缺口流中的完整单包 HTTP 可能仍产生阶段 4 单包证据。
- 重新流分析取消或失败时保留上次有效结果；成功导入、清空或继续抓包使旧流结果失效。保存仍写全部原始包，流分析不修改包对象或 PCAP 内容。
