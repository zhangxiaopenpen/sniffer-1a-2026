## 阶段 1 — 命令行真实抓包

### 已实现

- 新增 `sniffer_cli.py`，支持列出网卡、交互选卡及 `--iface` 明确选卡；提供 `loopback` 回环别名。
- 列表显示序号、名称、描述、IPv4、默认建议/回环标记和设备标识。无参数运行可回车选择默认建议或输入 `q` 取消；非交互调用必须提供 `--iface`。
- 默认捕获上限为 20 包、30 秒，数量和超时以先达到者为准；相应参数为 `0` 时不限制该项，支持 `Ctrl+C` 停止。
- 逐包显示序号、时间、长度和摘要，结束时显示实际包数。使用 `store=False`、`promisc=False`，不保存文件；未实现 GUI 或协议筛选。
- 已在新项目中创建独立 `.venv` 并按 `requirements.txt` 安装依赖；Python 3.14.3、Scapy 2.8.0、PySide6 6.12.0，`pip check` 无冲突。Npcap 服务为 Running，`conf.use_pcap=True`。

### 离线验证

- 使用模拟对象验证命令行参数、网卡选择和抓包调用等逻辑；这些测试不作为真实流量捕获的证据。

## 阶段 2 — 图形界面、稳定性与保存

### 已实现

- `main.py` 提供 GUI 入口，`ui_layout.py` 提供莫兰迪浅色布局。网卡列表显示名称与 IPv4，标记默认建议和回环接口；八列表格与下方详情支持查看基础协议字段及捕获时的原始十六进制字节。
- `capture_engine.py` 使用后台线程抓包，不向 GUI 逐包发送信号；`PacketBuffer` 维护有界队列，界面每 100 ms 最多取出 250 包批量加入表格。
- GUI 默认保留 1000 包，空数据时可设 10–10000 包；保留原始字节预算为 32 MiB，达到任一上限后自动停止。待处理缓存上限为 2048 包或 8 MiB 原始字节；这些预算不代表 Python 进程总内存上限。
- 明确区分收到、保留、应用丢弃、已显示和待处理；收到仅指进入本程序回调的包，应用丢弃分别记录缓存丢弃和上限丢弃，不作为网卡或 Npcap 总丢包统计。
- 开始、手动停止、自动限额停止、缓存排空和保存采用明确状态。停止后在同一网卡可继续累计；有数据时锁定网卡和上限，清空后恢复修改。保存需等待后台退出且缓存排空。
- 保存采用稳定包快照，在目标同目录写入临时文件，成功后原子替换实际选定路径；保留包顺序、原始字节、纳秒时间和线路长度。失败时保留窗口数据和原有目标文件。
- 关闭窗口异步等待抓包/保存线程结束和缓存排空；保存失败会取消关闭。清空和退出不会自动保存，也没有未保存提示，需要用户提前保存所需数据。驱动永久无响应时仍可能持续等待，未承诺固定退出时限。
- 阶段 1 命令行入口保留；阶段 2 没有新增依赖，没有实现过滤、文件导入、域名查询或 TCP 流功能。
