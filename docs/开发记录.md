## 阶段 1 — 命令行真实抓包

### 已实现

- 新增 `sniffer_cli.py`，支持列出网卡、交互选卡及 `--iface` 明确选卡；提供 `loopback` 回环别名。

## 阶段 2 — 图形界面、稳定性与保存

### 已实现

- `main.py` 提供 GUI 入口，`ui_layout.py` 提供莫兰迪浅色布局。网卡列表显示名称与 IPv4，标记默认建议和回环接口；八列表格与下方详情支持查看基础协议字段及捕获时的原始十六进制字节。
- `capture_engine.py` 使用后台线程抓包，不向 GUI 逐包发送信号；`PacketBuffer` 维护有界队列，界面每 100 ms 最多取出 250 包批量加入表格。
- GUI 默认保留 1000 包，空数据时可设 10–10000 包；保留原始字节预算为 32 MiB，达到任一上限后自动停止。待处理缓存上限为 2048 包或 8 MiB 原始字节；这些预算不代表 Python 进程总内存上限。
- 明确区分收到、保留、应用丢弃、已显示和待处理；收到仅指进入本程序回调的包，应用丢弃分别记录缓存丢弃和上限丢弃，不作为网卡或 Npcap 总丢包统计。
- 开始、手动停止、自动限额停止、缓存排空和保存采用明确状态。停止后在同一网卡可继续累计；有数据时锁定网卡和上限，清空后恢复修改。保存需等待后台退出且缓存排空。
- 保存采用稳定包快照，在目标同目录写入临时文件，成功后原子替换实际选定路径；保留包顺序、原始字节、纳秒时间和线路长度。失败时保留窗口数据和原有目标文件。
- 关闭窗口异步等待抓包/保存线程结束和缓存排空；保存失败会取消关闭。清空和退出不会自动保存，也没有未保存提示，需要用户提前保存所需数据。驱动永久无响应时仍可能持续等待，未承诺固定退出时限。
- 阶段 1 命令行入口保留；阶段 2 没有新增依赖，没有实现过滤、文件导入、域名查询或 TCP 流功能。

## 阶段 3 — 显示筛选与经典 PCAP 导入

### 方案范围

阶段 3 在阶段 2 GUI、保存和异步状态基础上增加协议/IP/CIDR/端口显示筛选和经典 PCAP 文件导入。筛选只改变表格显示，保存始终使用完整源数据；导入成功后进入文件模式，清空后才能恢复实时抓包。域名分析、TCP 流重组和 PCAPNG 明确留到后续阶段。

### 已实现

- `packet_filter.py` 新增 `FilterSpec`、筛选输入校验和 `PacketFilterModel`。支持“全部、HTTP、TCP、UDP、IPv4、IPv6、ICMP、ICMPv6”，支持 IPv4/IPv6 地址与 CIDR、0–65535 端口，多条件 AND，以及任一端地址/端口匹配。
- HTTP 筛选只识别最外层直属 TCP 载荷中的完整 HTTP/1.0 或 HTTP/1.1 起始行；TLS、UDP、跨 TCP 分片和隧道内层不误判为 HTTP。ICMPv6 按最外层直属协议识别。
- GUI 使用 Qt 代理模型保持源行映射。筛选后详情通过 `mapToSource()` 找回原始行，非法条件保留上一组有效筛选，Enter 键可应用 IP/端口条件，莫兰迪样式覆盖新增输入框。
- `pcap_io.py` 新增经典 PCAP 读取线程，支持四种常见 magic、微秒/纳秒时间戳、大小端和链路类型校验；拒绝 PCAPNG、截断文件、异常长度和错误版本。读取结果在校验完成后一次性发布，取消或失败不会污染当前界面。
- GUI 增加“打开 pcap”。读取期间锁定相互冲突的操作；成功读取后替换模型和缓存并进入文件模式，失败/取消恢复旧模型、缓存、筛选和源文件状态；清空后恢复实时抓包。超过包数或字节预算时仅发布前缀并明确提示后续数据未读取或校验。
- 保留阶段 2 的保存、详情、异步关闭和有界缓存行为。导入超过待显示队列 2048 包时逐包消费，避免把合法文件截断为队列上限。
