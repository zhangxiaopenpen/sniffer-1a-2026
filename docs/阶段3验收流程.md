# 阶段 3 验收流程：显示筛选与经典 PCAP 导入

本文用于验收阶段 3。请先在 PowerShell 中进入新项目目录；旧目录 `sniffer_1a` 不参与本阶段操作。

```powershell
Set-Location 'D:\研一课程\软件与系统安全\sniffer_1a_git'
.\.venv\Scripts\python.exe -X utf8 .\main.py
```

## 一、准备可观察的数据

1. 窗口打开后，在“网卡”下拉框选择带“默认建议”的网卡。
2. 点击“开始抓包”，等待状态变成“正在抓包”。
3. 在浏览器打开任意网页，例如 `https://www.baidu.com/`，再等待 3–5 秒。
4. 点击“停止”，等待状态显示“已停止”且计数中的“待处理 0”。
5. 表格中应出现包记录；单击某一行，下方“数据包详情”应显示 Scapy 字段和“十六进制原始数据”。

如果没有方便的实时流量，也可以直接使用已有的经典 PCAP，例如此前保存的 `D:\研一课程\软件与系统安全\sniffer_1a\capture.pcap`。该文件只用于本地验收，不要复制到 Git 仓库。

## 二、验收协议、IP 和端口筛选

1. 在“协议”下拉框选择 `TCP`，点击“应用筛选”。表格只显示 TCP 包，计数中的“保留”数量不应被改变。
2. 将协议改为 `UDP` 或 `IPv4`，再次应用，确认显示结果变化。
3. 在 IP 输入框输入一个表格中实际出现的地址，例如 `192.168.1.1`，点击应用。也可以输入网段，例如 `192.168.1.0/24`；带主机位的 CIDR 也会按网段处理。
4. 在端口输入框输入 `80`、`443` 或表格中实际出现的端口。协议、IP、端口同时填写时必须同时满足；IP 和端口均允许匹配源端或目的端。
5. 在 IP 或端口输入框按 Enter，也应触发应用筛选。
6. 点击“重置筛选”，表格应恢复显示全部保留数据。
7. 输入非法 IP（如 `not-an-ip`）或非法端口（如 `70000`），点击应用。提示应包含“未改变/上一组有效条件”，表格和上一组有效条件保持不变。
8. 应用筛选后点击第一行，详情必须对应筛选结果中的那一条原始包，不能错位到源数据的第一行。

HTTP 筛选只识别明文 TCP 起始行，不能识别 HTTPS 加密内容，也不会重组跨 TCP 分片的 HTTP 行。ICMPv6 作为独立协议选项可在存在相应流量时验证。

## 三、验收经典 PCAP 导入

1. 如果当前窗口有未保存数据，先点击“保存 pcap”保存到临时位置。
2. 点击“打开 pcap”，选择一个经典 `.pcap` 文件。若当前有数据，确认“打开成功将替换当前数据”。
3. 读取期间观察按钮：开始、清空、保存和再次打开应暂时不可用；窗口仍能响应操作。
4. 读取成功后，状态应显示“文件模式：文件名”，表格内容应替换为文件中的记录；可继续筛选、查看详情和保存。
5. 导入后点击“开始抓包”，应提示当前为文件模式，不能直接启动实时抓包。
6. 点击“清空”，确认表格和计数归零，网卡控件重新可用；之后可以重新选择网卡并开始实时抓包。

导入失败保护：在文件对话框中选择“所有文件”后打开一个普通文本文件，程序应显示读取失败，原来的表格、计数、筛选条件和实时模式应保留。读取期间点击“取消读取”，也应保留替换前的数据。

程序只支持经典 PCAP，不支持 PCAPNG。达到默认 1000 包或 32 MiB 保留预算时，PCAP 导入只发布已读取的前缀并给出“未读取或校验”提示。

## 四、保存和回归检查

筛选后点击“保存 pcap”，保存文件应包含全部源数据，而不是当前筛选结果。可再次使用“打开 pcap”读取保存文件并比较包数量。

运行自动化回归测试：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

阶段 3 开发验证结果应为 100 项测试全部通过，其中包括 12 项筛选测试、15 项经典 PCAP 测试和 7 项 GUI 集成测试；阶段 2 原有 66 项回归也必须继续通过。

## 五、阶段 3 范围

本阶段包含协议、IP/CIDR、端口和经典 PCAP 文件导入，以及筛选、导入、取消、失败和清空后的状态保护。域名查询、DNS 关联、TCP 流重组、PCAPNG 和 HTTPS 解密属于后续范围。
