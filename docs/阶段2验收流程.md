# 阶段 2 验收流程

阶段 1 已通过用户审核。本页用于验收阶段 2 的莫兰迪浅色 GUI、实时抓包、详情查看、停止、清空和 PCAP 保存。阶段 3 的过滤与文件导入，以及后续域名、TCP 流功能尚未开始。

## 打开新项目的图形界面

本机依赖与 Npcap 已准备好，无需重新安装，也无需激活虚拟环境。打开 PowerShell，复制下面两行执行：

```powershell
Set-Location 'D:\研一课程\软件与系统安全\sniffer_1a_git'
.\.venv\Scripts\python.exe -X utf8 .\main.py
```

确认使用的是新目录 `sniffer_1a_git`，不是旧目录 `sniffer_1a`。运行后应看到标题含“第二阶段”的窗口，背景为浅米色、灰绿色等莫兰迪浅色；上方有网卡、“开始抓包”“停止”“清空”“保存 pcap”和“最多保留”，中间是包列表，下方是数据包详情。

首次打开默认“最多保留”为 1000 包。网卡列表应包含名称、IPv4，并标记默认建议和回环接口。窗口可以调整大小，表格列宽和列表与详情之间的分隔条可以拖动。

## 默认网卡抓包与手动停止

- 选择带“默认建议”标记的网卡，保留默认 1000 包。
- 点击“开始抓包”，等状态从“正在打开网卡”变为“正在抓包”。
- 打开浏览器，访问自己常用的网页，观察表格新增数据行、计数变化。默认建议来自当前系统接口配置；若浏览器实际通过其他网卡联网，需停止并清空后改选相应网卡。
- 表格应有八列：编号、时间、源地址、目的地址、协议、源端口、目的端口、长度。不同协议的端口可能显示 `-`，这是正常情况。
- 点击“停止”。状态可能先显示“正在停止抓包”或“正在整理剩余数据”；等到“已停止”且“待处理 0”后，再观察几秒，表格行数与计数应保持不变。
- 此时“保留”和“已显示”应相同，且“保存 pcap”可用。若已提前达到上限，程序也会自动停止，按相同方式等待排空。

若需要保留本次数据，先按下文保存。未达到上限时，停止后可直接点击“开始抓包”，在同一网卡继续累计，原有行和编号保留。已有数据时不能换网卡或改保留上限，需停止、保存所需数据并清空后再改。

## 回环 ICMP、字段与原始数据

- 确认已停止且“待处理 0”；如需保留当前数据，先保存，然后点击“清空”。
- 确认表格与详情为空、各包数归零；选择网卡名称中带 `[回环]` 标记的接口。若同时带其他标记，以包含“回环”为准。
- 点击“开始抓包”，务必等状态显示“正在抓包”。
- 打开**第二个 PowerShell 窗口**，执行：

```powershell
ping 127.0.0.1
```

- 回到 GUI 点击“停止”，等“已停止”且“待处理 0”。
- 查找协议为 `ICMP`、源地址和目的地址为 `127.0.0.1` 的行，单击选中。
- 下方详情应出现协议字段，能找到 ICMP 的请求或应答信息；向下滚动可看到“十六进制原始数据”及以空格分隔的十六进制字节。

回环接口可能同时有其他本机流量；本阶段没有筛选功能，不要求所有行都是 ICMP，也不要求总包数固定。若在运行 `ping` 前已达到上限，先清空，将上限适当调大后重试。

## 保存并确认文件

- 保持停止且“待处理 0”，记下“保留”和“已显示”的包数。
- 点击“保存 pcap”，在对话框中选择新项目目录，文件名填 `阶段2验收.pcap`，点击保存。若文件已存在，按对话框确认是否覆盖，或使用新文件名。
- 等状态出现“已保存 N 个数据包”及实际保存路径。保存期间其他抓包和数据操作按钮会暂时不可用。
- `N` 应与保存前的“保留”“已显示”一致。不要要求它等于“收到”：应用缓存或保留上限可能导致应用丢弃，丢弃的包不会被保存。
- 在文件资源管理器中打开状态栏显示的路径，确认文件存在。若使用上述目录，可在第二个 PowerShell 窗口执行：

```powershell
Get-Item -LiteralPath 'D:\研一课程\软件与系统安全\sniffer_1a_git\阶段2验收.pcap' | Select-Object FullName, Length
```

可选：用现有 Scapy 读取文件，核对保存数量，无需安装新工具。在第二个 PowerShell 窗口执行：

```powershell
Set-Location 'D:\研一课程\软件与系统安全\sniffer_1a_git'
.\.venv\Scripts\python.exe -X utf8 -c "from scapy.utils import rdpcap; p = rdpcap('阶段2验收.pcap'); print('文件包数:', len(p))"
```

若选择了其他路径，以 GUI 状态栏显示的实际路径为准，并相应修改检查命令。GUI 的文件导入尚未实现；上述回读只是验收时的可选命令。

保存失败时会显示错误，窗口中的包仍保留，原有目标文件不会因本次失败被覆盖；请换到可写目录再保存。保存中关闭窗口会等待保存结束；若保存失败，会取消关闭以保留数据。

## 清空、10 包自动停止与重复启停

- 保存需要的数据后，点击“清空”。表格、详情和计数应归零，网卡和上限重新可选；上限数值本身不会自动恢复为 1000。
- 将“最多保留”改为 `10`，选择回环网卡，点击“开始抓包”。
- 若尚未自动停止，等状态显示“正在抓包”后，在第二个 PowerShell 窗口执行：

```powershell
ping -n 10 127.0.0.1
```

- 程序应在保留 10 包后自动停止并排空，提示已达到保留上限；“保留”和“已显示”为 10，“待处理”为 0。背景流量也可能很快填满 10 包，所以本项不要求保留包全是 ICMP。
- 达到上限后“开始抓包”不可用。先保存需要的数据并清空，将上限恢复为 `1000`，再开始新一轮。
- 连续做三轮“开始抓包”后很快点击“停止”。每一轮都先等“已停止”且“待处理 0”，再开始下一轮；窗口应能响应，不出现报错或退出。

## 关闭窗口

请先保存需要的数据。本阶段没有退出前的未保存提示，也不会自动保存。

- 空闲状态点击窗口右上角关闭，应能正常退出。
- 重新运行 `main.py`，开始抓包后点击右上角关闭。窗口会先等待抓包后台退出并整理待处理包，然后关闭；此过程不保存本次数据。
- 如状态显示“正在等待驱动退出，窗口仍可响应”，说明后台尚未结束。停止与关闭都采用异步等待；驱动永久无响应时，窗口也可能一直等待，不能保证固定时间内退出。

## 计数和限制的含义

| 项目 | 含义 |
| --- | --- |
| 收到 | 已进入本程序抓包回调的包数；不是网卡看到的全部包数 |
| 保留 | 已接受并保存在当前数据集中的包，包括已显示和待处理 |
| 应用丢弃 | 因本程序缓存或保留上限而丢弃的包，不含网卡或 Npcap 驱动的丢包统计 |
| 已显示 / 待处理 | 已进入表格的包数 / 等待批量加入表格的包数 |
| 保留上限 | 默认 1000 包，可设 10–10000 包；或 32 MiB 原始数据，达到任一上限自动停止 |
| 待处理缓存 | 最多 2048 包或 8 MiB 原始数据，满时记录应用丢弃 |

应满足 `收到 = 保留 + 应用丢弃`。32 MiB 限制只统计包的原始字节，不是进程总内存上限。界面每 100 ms 最多追加 250 包，因此停止后短暂整理剩余数据是正常行为。
